## 1. 给执行任务的 GPT：目标和边界

你的目标是让**当前这位用户自己的连接**完成目录读取、3D 预览、交互修改和再次读取。作者账号成功、网站能打开、插件可被 `@` 选中，都不能代替这次验收。

- 如果你有浏览器或插件管理能力，请在用户授权范围内实际安装、检查设置和测试；遵守你所在环境对登录、OAuth 同意和条款的操作要求。
- 如果工具需要动态发现，请先搜索 LOOP 或下文工具名。不要因为初始工具列表没展开，就直接断言“没有接口”。
- 如果你只有文字对话能力，无法替用户控制设置页，请如实说明，并用本文件指导用户完成必要点击；不能声称已经替他安装。
- 附件不会凭空给你增加浏览器权限，也不会把另一个人的 MCP 连接转移给你。
- 使用现有线上服务。不要为这次安装克隆项目、启动本地服务器、部署新站点、配置隧道，或索要 OpenAI API key。
- 默认只读测试，不保存、不下单。可选写入测试在第 7 节，须得到当前使用者的相应指令。
- 不要通过图像生成代替 LOOP 的 3D 卡片，不要编造工具结果、报价、订单或授权链接。
- 不要读取或发送别人的 Cookie、令牌、OAuth 回调参数、私钥、验证码、历史设计或订单。

## 3. 在队友自己的账号里创建或刷新连接

### 3.1 先确定入口

优先使用电脑浏览器打开 ChatGPT 官网，并登录当前使用者自己的账号。当前官方流程是：打开 **Plugins / 插件**，通过加号进入 **Add custom MCP server / 添加自定义 MCP 服务器**，配置后创建为个人插件，再安装。[OpenAI Docs 安装流程](https://developers.openai.com/plugins/quickstart)

界面文字可能变化。按实际页面操作，不要虚构菜单，也不要反复让用户寻找根本没有的 Connect 按钮。如果该账号没有添加自定义 MCP 的入口，记录客户端、账号可用入口和限制，停在“账号或界面能力阻塞”；提示词无法解锁账号功能。此时可用第 9 节独立网页试用，但不能把它算成 ChatGPT 安装成功。

### 3.2 处理已有的旧 LOOP

先检查旧条目的 **MCP URL 和认证方式**：

1. 地址完全相同且为 OAuth：优先使用页面实际提供的 **Refresh / 刷新**，更新工具定义，然后新开聊天。
2. 地址错误、是旧临时隧道、设为 No authentication，或无法确认：创建一个名字明确的 `LOOP Demo` 新个人连接，使用第 2 节配置。
3. 不要一上来删除全部插件、清空浏览器 Cookie、退出所有账号或清理历史记录。它们不是安装前提，还可能改变 LOOP 访客工作台。
4. 若需要断开一个确认失效的 LOOP 连接，应只处理该连接，说明重新授权的影响；保留旧记录信息以便排查，不操作其他插件。

官方对自定义 MCP 的更新方法是刷新连接元数据，再用新聊天重测；不能用旧聊天中的工具清单判断更新是否生效。[OpenAI Docs 元数据刷新](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata)

### 3.3 创建后还要安装并在 Work 中启用

创建个人连接后，到个人插件列表打开它，使用实际页面提供的安装入口。只有“立即试用 / Try now”时，可以先进入试用，但随后仍需验证真实工具调用。

回到 ChatGPT 首页，在当前界面提供 **Chat / Work** 切换时，选择 **Work**，新建 Work 聊天，再在输入框输入 `@`，选中刚才的 **LOOP Demo**。若必须由用户开新聊天，把下一节的目录测试提示词交给他，让他在那个新聊天执行。

**本项目已验证的 3D 工作流程是在 ChatGPT Work 中完成的。** 不要把旧的普通 Chat 对话、生成图片的对话，或单纯输入“@LOOP”文字当作已经启用了插件。官方 Quickstart 也采用 Work 新聊天和真正的插件提及进行测试。[OpenAI Docs Quickstart](https://developers.openai.com/plugins/quickstart)

## 4. OAuth：让队友自己的连接完成授权

在新 Work 聊天中选中插件后，先发送以下提示词：

```text
请使用我当前选中的 LOOP Demo 插件，实际调用 loop_get_catalog，参数为 {}。
只报告真实返回的模板 ID 和币种，不保存设计，不创建订单，不生成图片。
如果工具需要授权，请使用宿主提供的真实 OAuth 连接流程；不要自己编造授权 URL。
如果当前上下文看不到工具，请先用可用的工具发现能力查找 LOOP；仍不可用时明确说明。
```

### 4.1 尚未授权时

官方 OAuth 流程在首次工具使用时发起授权码和 PKCE 流程；因此“创建或安装时没立刻弹窗”本身不能证明失败。[OpenAI Docs OAuth](https://developers.openai.com/plugins/build/auth#oauth-flow)

跟随 ChatGPT 真正显示的连接/授权操作。LOOP 自身的同意页面标题是 **“连接你的 LOOP 工作台”**，同意按钮是 **“授权连接”**。当前使用者核对后同意，返回 ChatGPT，再重试目录工具。

如果授权页在外部浏览器打开，确认仍是当前使用者打算使用的浏览器环境。不要让作者代点授权，也不要转发作者的回调地址。

### 4.2 没弹窗但工具成功

如果目录工具已真实返回结果，连接可能已有有效授权。标记“沿用有效授权”，继续预览测试；不要为了看到一个弹窗强行断开健康连接。

### 4.3 没弹窗且没有工具结果

按顺序查：

1. 当前是否为新的 Work 聊天，是否真正选中刚创建的插件。
2. 工具发现后是否能看到 LOOP 的业务工具，实际调用是否发生。
3. 连接页 URL 是否准确，是否为 OAuth/DCR，是否能刷新工具定义。
4. 宿主是否真的给出连接提示、OAuth 报错或其他可验证错误。

普通回复里写“需要授权”，或模型生成一个“重新调用”按钮，只表示文字建议；必须观察真实连接流程或真实工具结果。不要不断重发同一句设计需求。

### 4.4 不存在可转发的通用 OAuth 授权网址

`https://loop-charm-studio.vercel.app/authorize` 是协议端点，不能单独当作一键绑定链接。有效流程需要宿主提供这条连接的客户端、回调、state、resource 和 PKCE 参数；让队友自己的 ChatGPT 发起它。

LOOP 授权连接的是**该浏览器的访客工作台**，不是按物理机器认证，也不是已验证的个人账户。不同浏览器配置、无痕窗口或清掉访客 Cookie，可能得到另一个工作台。多台机器不能靠复制别人的授权 URL 或令牌实现同一个连接。

## 5. 工具与最新能力核对

截至本文件更新日，服务器通过 `tools/list` 提供以下 11 个工具。宿主可能在工具名前添加命名空间；以末尾功能名识别即可。

| 工具 | 用途 |
| --- | --- |
| `loop_get_catalog` | 真实目录、兼容规则、模板、默认有效配置 |
| `loop_preview_design` | 可交互 3D 卡片、报价、配件选择 |
| `loop_quote_design` | 服务端验证并计算报价 |
| `loop_save_design` | 创建或更新当前工作台的草稿 |
| `loop_list_designs` | 当前工作台草稿列表 |
| `loop_get_design` | 按返回的实际 ID 读取自己的草稿 |
| `loop_prepare_test_order` | 准备准确配置和报价，不创建订单 |
| `loop_confirm_test_order` | 明确确认后创建模拟订单 |
| `loop_list_orders` | 读取当前工作台的模拟订单 |
| `loop_suggest_design` | 可选服务端 AI 方案，不是默认验收前提 |
| `loop_get_preview_asset` | 卡片渲染器内部读取 3D 素材 |

`loop_get_preview_asset` 是 app-only 工具，模型端可能看不到，不能因此判定安装失败。普通 GPT 也未必能直接取得原始 `tools/list`；此时如实记录能发现并调用的业务工具，别编造“11 个全部已加载”。

默认用 **GPT 自己推理 → 读取目录 → 构造完整有效配置 → 调用预览**。不必调用 `loop_suggest_design`，也不要求队友提供服务器模型 API key。该可选工具失败，应单独报告，不能直接把目录和 3D 能力判为失败。

## 6. 默认只读验收：按顺序做完

每阶段均记录：实际工具名、返回摘要、实际 UI 现象、PASS / FAIL / 尚未验证。不能仅凭自然语言回复判 PASS。

### T1：读取目录和授权验收

执行第 4 节目录提示词。通过条件：`loop_get_catalog({})` 确实返回真实目录，模板含 **cord / chain / hero**，币种 **USD**。记录是本次新授权还是沿用有效授权，不泄露授权参数。

未通过 T1 时先排查连接，不继续假装设计成功。

### T2：显示真正的 3D 卡片

```text
使用刚才 LOOP 返回的真实目录，设计一个配棕色包的樱桃和珍珠包挂。
采用 hero 模板，金色五金；设计名称为 Teammate Check。
配件 ID、连接件、颜色和全部插槽必须取自目录，空插槽填 null，lockedSlots 初始为空。
请实际调用 loop_preview_design，展示可编辑 3D 卡片和服务端计算的 USD 报价。
不要使用图片生成，不要保存，不要创建订单。
```

通过条件：工具无业务错误，配置和报价来自服务端；卡片中实际出现 3D 物件，使用者或具备浏览器能力的 GPT 能旋转/缩放，并切换包包视图。图片、视频、文字色板、原始 JSON 或一直转圈都不能代替这个检查。

本次预期 UI 资源为 `ui://loop/design-v5.html` 或服务端后来提供的新版本。不要自己拼接这个 URI 当网页打开；由宿主加载工具声明的 UI。

如果出现 **Couldn't display LOOP / Try again**，使用真实卡片里的重试入口一次，等待加载结果。恢复后标记“重试后通过”，不能报一次成功。如果仍失败，保留已成功的工具结果，把 UI 标记 FAIL，转第 8 节，不无限刷新。

如果你无法查看卡片或控制 3D，请让当前用户完成这几个动作；在拿到实际反馈前，状态是“工具通过，UI 尚未验证”。

### T3：锁定配件、修改和显示替换卡片

```text
使用 Teammate Check 的最新完整配置，把 hero 的 main 樱桃设为锁定。
保持樱桃、珍珠和其他设置，只把 metalTone 改成 silver，然后实际调用 loop_preview_design。
再用最新完整配置调用 loop_preview_design，selectionSlot 设为 accent，显示兼容配件的图片选择卡。
在我选中前不要替换珍珠。不要保存，不要创建订单。
```

通过条件：`lockedSlots` 包含 `main`，樱桃和珍珠的实际 ID 保持，金属色变为 silver，新的 3D 卡片正确显示；accent 兼容选项有图片和真实报价信息。不要只返回一份文字备选清单。

卡片中点选或修改后，以最新卡片上下文为准，不能再拿最初旧配置覆盖当前状态。

### T4：再次调用，确认连接能继续使用

```text
请再次实际调用 loop_get_catalog，参数为 {}。
报告这次工具是否成功、模板 ID 和币种。
不要保存设计，不要创建订单，不生成图片。
```

通过条件：同一连接下再次真实调用成功。此测试只证明当前连接可继续工作，不能宣称已完成跨设备、长期刷新令牌或手机端验收。

**T1–T4 都通过，才可以报告“这个队友账号的当前桌面连接已通过基础使用验收”。** UI 无法观察则保留相应未验证项。

## 7. 可选：保存、重开与模拟订单

基础安装测试不要求写入。只有当前使用者另外要求测试保存时，才保存一个样例：

1. 用 `loop_save_design` 保存当前 `Teammate Check`，记录工具实际返回的 ID。
2. 用 `loop_list_designs` 的 `limit: 1` 读取最新记录，再用 `loop_get_design` 读取该 ID。不要展开无关历史记录。
3. 修改时保留该 ID：预览传 `designId`，更新保存传 `id`，验证更新的是同一草稿。

只有当前使用者明确要求测试订单时，才准备结算。必须先显示 `loop_prepare_test_order` 返回的**准确设计、逐项 USD 报价和无真实交易说明**，再等待他单独确认这笔准确订单。作者以前同意的 $12 测试订单不代表这位队友同意创建新订单。

得到本次明确确认后，使用未改变、未过期的 `confirmationToken` 调用 `loop_confirm_test_order`，然后 `loop_list_orders(limit: 1)` 验证回执和 `test_confirmed`。不要在聊天或报告中展示 token。配置或价格变化就重新准备并确认；不重复准备多笔订单来“试通”。不要访问真实付款或发货页面。

## 8. 失败时按证据定位，不要乱改

| 实际现象 | 下一步 |
| --- | --- |
| 只生成图片或文字搭配 | 查 Work 模式、真实 `@` 选择、工具发现和调用记录；返回 T1，不能记为 3D 通过 |
| 已 `@` 选中，但工具缺失 | 刷新这条自定义连接的元数据，新开 Work 聊天；仍缺失时记录连接设置及可用工具，不凭空伪造调用 |
| 只有 Try now，没有 Connect | 用新 Work 聊天调用目录触发宿主授权；若目录直接成功，则已有授权，无需强求弹窗 |
| 页面强制填写 Client ID / Secret | 查是否选错认证或注册方式，优先找 DCR；没有该选项就报告实际界面限制，不填猜测值、不借作者凭据 |
| 授权后仍提示未授权 / 重复跳转 | 保留准确错误及发生步骤，核对固定域名、OAuth/DCR 和浏览器配置；只对这条 LOOP 连接处理重连，不清全局 Cookie |
| 工具成功，但卡片失败或没有 3D | 记录卡片错误并重试一次；标记 UI FAIL，而不是 OAuth FAIL。必要时测试电脑网页客户端，分别记录结果 |
| 网站与卡片收藏不同 | 查授予同意时的浏览器访客工作台；不要搬运他人令牌，不承诺跨浏览器自动同步 |
| 直接在地址栏打开 `/mcp` 是 401 | 未授权 GET 被保护是预期行为；应由 MCP 客户端走 POST 和 OAuth，不能仅凭这个判服务器宕机 |
| 缺少自定义 MCP / Work 入口 | 记录当前账号与客户端的能力阻塞；不能靠公开 Demo、换提示词或假造工具绕过 |
| `loop_suggest_design` 失败 | 单独记录该可选能力；使用目录加 GPT 推理再预览，不索要使用者 API key |

一次元数据刷新、新 Work 聊天和一次有证据的卡片重试后仍失败，应提交报告，不继续循环“已重新连接，请再试试”。发生异常也不要改成 No authentication 来绕过 OAuth。
